### バージョンと Core Profile

LearnOpenGL の基礎編は OpenGL 3.3 Core を使う。以前のコードでは 4.1 Core のコンテキストを要求していた。4.1 Core でも、基礎編で扱う機能を学べる。

GLFW、GLAD、OpenGL のバージョンは、それぞれ別のもの。

現在の GLAD ファイルには OpenGL 4.6 までの関数宣言が含まれている。実際に使える機能は、実行時に作成されたコンテキストによって決まる。後で関数を読み込むときは、このプロジェクトにある GLAD 1 の `gladLoadGLLoader` を使う。

Core Profile は、多くの古い機能を除いた、現代的な機能のまとまり。「3.2 は Immediate mode、3.3 から Core に変わった」という区別ではない。

### コンテキストとウィンドウ

**コンテキスト（context）**は、描画の状態や描画用リソースに関する情報を持つ、OpenGL の実行環境。

通常、`glfwCreateWindow` はウィンドウとコンテキストを一緒に作る。OpenGL 関数を使う前に、`glfwMakeContextCurrent` でそのコンテキストを現在のスレッドで使う対象にする。

ウィンドウを扱う基本的な順序：GLFW の初期化 → 作成条件の設定 → ウィンドウの作成 → イベント処理の繰り返し → 終了処理。

各関数の引数・戻り値・呼び出す場所は、[共通資料の GLFW 関数の早見表](reference.md)にまとめている。

`GLFWwindow*` は、ウィンドウを操作するときに使うハンドル。`if (!window)` は、ウィンドウの作成に失敗したかを調べる書き方。

ウィンドウの幅・高さはスクリーン座標で指定する。Retina ディスプレイでは、描画先の実際のピクセル数と一致するとは限らない。

`glfwSetErrorCallback` は、エラーが起きたときに呼んでもらう関数を登録する。エラー番号や説明を出力するために使える。

参考：[GLFW 3.4 入門](https://www.glfw.org/docs/3.4/quick_guide.html)、[ウィンドウの作成条件とサイズ](https://www.glfw.org/docs/3.4/window_guide.html)。

### 状態とオブジェクト

OpenGL は、現在の設定を記憶して動作する「ステートマシン」として捉えられる。

- 状態を変更する関数：描画に使う設定を変更する。
- 状態を利用する関数：現在の設定に従って処理する。

OpenGL のオブジェクトは、設定やデータなどをひとまとまりにして扱う仕組み。

### 拡張機能（Extension）

標準の機能に加えて、実装が追加で提供する機能。使うときは、その環境で対応しているかを調べる。

以前のメモにあった `GL_ARB_extension_name` は説明用の仮の名前。その名前を条件式に書くだけで、実行時の対応状況を確認できるわけではない。

### GLAD と関数ポインタ

OpenGL の関数を利用するために、実行時に関数のアドレスを取得し、関数ポインタに保存する仕組みが使われる。GLAD は、この読み込み処理をまとめて行う。

手動で行う場合は、関数ポインタの型と変数を用意し、プラットフォームに応じた方法でアドレスを取得し、関数が利用できるかを確認する必要がある。

以前のメモの `wglGetProcAddress` は Windows 用。この macOS プロジェクトでは、GLAD と GLFW を使ってプラットフォームによる違いを扱う。
